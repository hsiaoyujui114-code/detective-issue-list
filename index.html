嚴重度說明：高＝資料已經分叉或功能會壞，先修；中＝文件與現況不符、或遲早出事；低＝整潔與可維護性。用下面的按鈕篩選，或搜尋關鍵字。ISSUE-14～24 是 2026-11-11 實際打開地圖頁面檢查後新發現的。

ISSUE-01高資料同步rpg · city-pulse · metro

cases.json 三個倉庫已經是不同版本，metro 那份缺三個欄位

問題：同一份 50 案資料存在三個倉庫，大小已經對不起來。metro 的版本明顯較舊，少了 chapter、diy_experiment、cross_case_clue 三個欄位——玩家在哪個入口玩，看到的案件資料就不一樣。

taipei-detective-rpg … cases.json = 536,111 bytes city-pulse-detective … cases.json = 536,102 bytes（與 rpg 差 9 bytes，也需比對） taipei-metro-detective-rpg … cases.json = 437,702 bytes（缺 chapter / diy_experiment / cross_case_clue）
修復方式與驗證
  1. 逐欄位比對三份 cases.json，確認最完整的一份為準（預期是 rpg 或 city-pulse）。
  2. 把基準版複製到其他倉庫；9 bytes 的差異也要查明是什麼，不要直接忽略。
  3. 在回報中寫明基準版來源與比對結果。
驗證：三份檔案 byte 數與雜湊值一致；隨機抽 5 案檢查三欄位都存在。
ISSUE-02高資料同步rpg

問題：共用資料檔在 rpg 倉庫是殘缺版，約只有完整版的四分之一。任何從 rpg 入口載入共用資料的功能，都可能拿到不完整的資料。

taipei-detective-rpg … shared-data.js ≈ 38 KB taipei-metro-detective-rpg / city-pulse-detective … shared-data.js ≈ 145 KB
修復方式與驗證

  2. 檢查 rpg 端引用 shared-data.js 的頁面，確認沒有寫死舊版才有的結構。
驗證：三個倉庫的 shared-data.js 大小與雜湊一致；rpg 的企劃書與案件頁開啟無主控台錯誤。

ISSUE-07中文件不符全部倉庫 · 企劃書

ISSUE-08中架構耦合metro · core

地圖倉庫的 server.js 硬引用兄弟目錄../taipei-detective-core，單獨 clone 跑不起來

問題：偵探核心 API 要靠兩個本機服務搭配：地圖倉庫的 localhost:3000 掛 core 的 localhost:3001。但 server.js 直接假設 core 就在隔壁目錄——任何人只 clone 一個倉庫，偵探功能就啟動不了，而且錯誤訊息不會告訴他原因。

修復方式與驗證
  1. README 明寫前置條件：需同時 clone 兩個倉庫並放在同一層目錄，兩個服務都要啟動。
  2. server.js 啟動時檢查 core 目錄是否存在，缺失時印出友善錯誤訊息說明缺什麼、去哪 clone。
驗證：只 clone 地圖倉庫時，啟動會得到清楚的提示而不是不明錯誤；雙倉庫就位時功能正常。
ISSUE-09中規劃落差企劃書 · 全部倉庫

規劃寫 PixiJS＋Socket.io，實際是自寫 Canvas＋ws——只改文件，不要換引擎

  1. 把文件改成兩段：「目前實作＝自寫 Canvas＋ws」與「未來若重構才考慮 PixiJS／Socket.io」。
  2. 不要真的動手換引擎——那會把能玩的遊戲弄壞，不在本清單範圍。
驗證：文件全文搜尋 PixiJS／Socket.io，只出現在「未來規劃」脈絡；遊戲試玩入口功能不變。
